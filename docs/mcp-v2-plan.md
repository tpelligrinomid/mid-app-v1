## Architecture

```text
Claude (claude.ai / Desktop / Code)
   │  MCP over streamable HTTP, Bearer token
   ▼
mcp.newnorth.com  ──CNAME──►  Render mid-app-v1  (Express)
                                 ├─ GET  /.well-known/oauth-protected-resource[/mcp]
                                 └─ POST /mcp  → authMiddleware → staff gate → McpServer (stateless) → tools
                                                    │                                   │
                                                    ▼                                   ▼
                              Supabase OAuth 2.1 server (issuer …/auth/v1)     user-scoped Supabase client (RLS)
                              consent page on the app (/.lovable/oauth/consent) + backend services (RAG chat, Databox, SEO…)
```

- **Auth:** Supabase's OAuth server (already enabled; dynamic client registration on) is the authorization server. Tokens it issues are normal Supabase user JWTs, so the existing `authMiddleware` validates them and attaches a **user-scoped client** — every query runs under RLS. Contract permissions therefore come from Pulse/Compass only, with no separate ACL.
- **Discovery:** the backend serves RFC 9728 protected-resource metadata (`resource: https://mcp.newnorth.com/mcp`, `authorization_servers: [https://<ref>.supabase.co/auth/v1]`) and answers unauthenticated `/mcp` calls with `401` + `WWW-Authenticate: Bearer resource_metadata="…"` — the same pattern v1 uses (verified working on the new project).
- **Staff gate:** after auth, reject `users.role = 'client'` and non-`active` users with a JSON-RPC error. Owner/admin-only tools (`create_release_note`, agency-wide metrics) keep their extra check.
- **Transport:** `@modelcontextprotocol/sdk` `McpServer` + `StreamableHTTPServerTransport`, stateless (new server per request, no session store) — fits Render's single service and scales horizontally.
- **Host routing:** requests arriving on `mcp.newnorth.com` may only reach `/mcp` and `/.well-known/*`; everything else on that host is 404, so the app API isn't exposed under the MCP name.
- **Audit:** every tool call writes a row to a new `mcp_tool_calls` table (user, tool, contract_id, redacted args, status, duration, error). Readable by owner/admin only (RLS).

## Build plan — v2.0

1. **Backend scaffolding:** add `@modelcontextprotocol/sdk` (pin an exact, ≥2-week-old version); `routes/mcp.ts` with discovery + `/mcp`; staff gate; host routing; audit table migration.
2. **Port tools** in batches (contracts → tasks/people → points/metrics → sentiment → search/notes/deliverables → writes). Reuse v1's queries; swap `@lovable.dev/mcp-js` `defineTool` for SDK `registerTool` with the same zod schemas.
3. **`compass_ask`:** wrap `streamChatResponse` (collect deltas into text; return `web_sources` and `context` sources).
4. **Test:** MCP Inspector and Claude Code against the Render URL (`claude mcp add --transport http mid https://mid-app-v1.onrender.com/mcp`), then a claude.ai custom connector. Check: OAuth sign-in via the consent page, a client account is refused, RLS scoping for a team member with limited contracts, audit rows written.
5. **Hostname:** add `mcp.newnorth.com` as a Render custom domain on `mid-app-v1`; CNAME in New North's DNS; update `resource` metadata.
6. **Roll out:** short how-to for the team (add connector → sign in); release note.
7. **Retire v1:** delete the `mcp` edge function from the Supabase project; remove `src/lib/mcp` and `@lovable.dev/mcp-js` from the frontend.
